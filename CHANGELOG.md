# Changelog

Changes that matter to someone using or reviewing Agentic-Datacenter. Each distribution follows semantic versioning once it has a first release; until then everything is version 0.0.0.

## Unreleased

No version has been released, and no benchmark result has been reported. This entry describes the repository as it is first made public: what it can do, what it cannot do yet, and the most recent changes. The history before that is in the git log and in the decisions under `docs/design/adr/`.

### What it can do

Plant and protocols

- A generic simulated data center (`profiles/generic_dc.yaml`) built from sixteen plant modules: utility supply, medium-voltage switchgear with protection relays, power trains with automatic transfer, generators, UPS, IT load, weather, chillers, thermal storage, pumps, PODs, electrical rooms, sensors, fuel, life safety and security. Every module is at fidelity `F1`. None is calibrated against a real facility.
- A deterministic kernel on simulated time. The same profile and seed give the same state hash, and a run can be captured and restored.
- A supervisory layer: point database, alarms, append-only hash-chained logs, sessions with four permission levels, a historian, and an operator API. Every write goes through one command service.
- IEC 62443 zones and conduits as data. Every request between zones is decided against the conduit model, and a refusal is logged.
- Simulated Modbus/TCP, BACnet/IP, SNMPv3, OPC UA and IEC 61850 MMS servers, read from the point database. The IEC 61850 package is GPLv3, serves on Linux only, and generates its SCL files (`agentic-datacenter scl export`). Servers bind only inside the simulator's own networks.
- Measured weather series as input to a scenario (`docs/guides/measured-weather.md`). No dataset is in the repository.

Governance gates and the REMORA binding

- A gate interface with four verdicts (`ALLOW`, `DENY`, `VERIFY`, `ABSTAIN`), a contract library (`contracts/`), and invariants that hold whatever the gate (`docs/reference/invariants.md`).
- Built-in gates: `null_gate`, `static_allowlist`, and three bindings to REMORA: `remora` (`DECISION_ONLY`), `remora_governed` (`GOVERNED`) and `remora_shadow` (`SHADOW`).
- REMORA is pinned by commit in `REMORA_PIN` and imported by one package only. The REMORA gates refuse to start unless the installed REMORA is the pinned commit. `agentic-datacenter contracts compile` turns the contract library into a signed ToolSpec bundle and a signed limit policy with REMORA's own tools.
- Gates from other projects: a Python package, a service over HTTP in any language (`http_gate`, wire format `agentic_datacenter.gate.http/1`), or a command per decision (`command_gate`). `agentic-datacenter gate check` runs the interface suite against any of them (`docs/guides/bring-your-own-gate.md`).

Scenarios and benchmark

- Twenty-seven scenarios, thirteen operational and fourteen adversarial, played by scripted agents: careful, hostile, drifting and flooding. The frozen version `benchmark-v1` has 23 of them; `AD-11` to `AD-14` are new on the main branch and are not in a frozen version yet.
- Counterfactual replay: a blocked proposal is replayed as if it had been carried out, to show whether the block avoided harm or cost a useful step. Every run is also compared with the same scenario and seed with no agent.
- `agentic-datacenter bench run` in four tiers (`docs/bench/TIERS.md`), in several processes or split over machines and merged. The result card is the same, byte for byte, however it was made.
- `agentic-datacenter demo`: three scenarios with no gate and with one, from the same seed, as a page with every decision and its record and as a one-page result report in HTML and Markdown.
- `agentic-datacenter whatif`: one proposed change played as a baseline, a physical branch and a governed branch.
- For a public test: `agentic-datacenter bench freeze`, hidden scenario variants drawn from a public randomness beacon, and a preregistration (`docs/bench/PUBLIC_TEST.md`, `docs/bench/PREREGISTRATION.md`).

Evidence and release check

- An evidence bundle per run: manifest, state hashes, decision records, change log and metrics. `agentic-datacenter scenario verify` checks a bundle against its manifest.
- `agentic-datacenter bench check` refuses a result card with a harmful execution, an invariant breach, a failed scenario criterion, a run with more harm than the same run with no agent, or anything missing (`docs/guides/release-gate.md`).
- `tools/gen_62443_matrix.py` writes the IEC 62443 matrix from a test run. No conformance is claimed.

Tooling

- Ten Python distributions in one `uv` workspace with one lock, and import-linter contracts for the boundaries between them.
- Requirement traceability: tests carry the requirement they verify, and `tools/traceability.py` fails when a requirement that is due has no passing test or no owner. `docs/reference/requirements.md` lists which requirements are due and which are still open.
- Reference pages generated from the code, and a strict documentation build.
- Workflows whose jobs run in one digest-pinned image, the benchmark runner excepted, with `tools/ci_local.py` to run the same jobs on a machine of your own.
- A devcontainer for GitHub Codespaces.

### What it cannot do yet

- `compose` mode is not built. Everything runs in one process (`inproc`).
- There is no language-model agent. The agents are scripted.
- No benchmark result has been reported. Season 1 runs on the frozen version `benchmark-v1`; its hidden track is drawn on 2026-12-02.
- No result has been reproduced on a second machine.
- The other differences from the design document are in its section 14.

### Recent changes

Added

- An equipment registry (ADR 0034). `equipment/` holds entries that give a module the values of a named make and model. Each entry records the source and line of every value, its rated conditions, how the module takes them, its tier (`factual`, `calibrated` or `vendor_verified`) and the rights to use and redistribute it. A gate in the tests refuses an entry without a pinned source, a licence text and both rights allowed. The first eight entries are chillers of the Modelica Buildings Library, made by `tools/equipment_modelica.py`. A bundle uses an entry as `registry:<id>`. The README is now organised by what each kind of contributor brings and gets back.
- The number of chillers is a parameter of `cooling.chw_plant` 0.3.0, `chillers`, 1 to 9 (ADR 0033). With three, every tag, port and state is as before. A fourth or later chiller gets points of its own and shares one of the three power feeds; a plant of fewer has no points for the chillers it lacks, so the contracts that name them do not fit it. The supervisory overview and the chiller alarms count the chillers from the plant.
- Bring your own data center, part 2 (ADR 0033). `agentic-datacenter facility check <bundle>` runs the plant for five minutes and reports which contracts load and which scenarios fit, each one that does not with what it lacks, as JSON and Markdown. `facility compile` writes the profile a bundle compiles to. `bench run --facility` and `scenario run --facility` run what fits. The card names the facility in a `facility` block, is labelled "result on a facility of its owner, not a benchmark result", and `bench check --publication` refuses it. `examples/byodc/` has six PODs of three kinds. The guide is `docs/guides/bring-your-own-datacenter.md`.
- Bring your own data center, part 1 (ADR 0033). A facility can be a directory of files, a *bundle*, with `datacenter.yaml` at its root, which compiles into an ordinary profile. A module use can name an equipment model, with its maker, model and evidence, and give single instances their own model or values, so PODs of different kinds sit side by side. Every value keeps its source or is marked assumed. Building a plant now refuses a parameter its module does not read, so a misspelt name no longer leaves the default in place without a word. `profile validate` and `run` read a bundle. The generic profile and its hash are unchanged.
- Keepalives in the format of shirudo (`shirudo.keepalive/1`), made and checked without a TPM (ADR 0032, proposed). `agentic_datacenter.governance.keepalive` encodes and parses bodies, signs quotes with deterministic software keys derived from the seed and the host, and checks a quote as `shirudo-quote-check` does: the same seven checks in the same order, with the bounds of shirudo's own parsers. It gives `ok` on shirudo's four vectors, which are copied with shirudo's BSD-2-Clause licence into `tests/fixtures/shirudo/`; `SHIRUDO_PIN` records the commit and the hash of every copied file. No host sends a keepalive yet, and no gate is told of one. `cryptography` is now a direct dependency of `agentic-datacenter-governance`.
- `benchmark-v1.1`, frozen for season 1, which now closes on 2027-01-13 at round `35679412` (`docs/bench/VERSION.json`; the record of `benchmark-v1` is in `docs/bench/versions/`). It has 27 scenarios, held-out variants that move every kind of event, the thermal shutdown of the IT load, and the plant interface (ADR 0029). See the preregistration, 2026-11-20 and 2026-11-21.
- `docs/reference/evidence-model.md`: the chain of records a run leaves, from scenario to consequence.
- `agentic-datacenter --help` lists every command, with one line each, including those added by other packages: `bench`, `data`, `demo`, `gate`, `scenario`, `whatif`, and `contracts` and `scl` when REMORA and the IEC 61850 package are installed. The line is the first line of the command's docstring.
- A ruleset for frozen benchmark tags (`.github/rulesets/benchmark-tags.json`): a `benchmark-*` tag cannot be moved or deleted. `docs/guides/bench-runner.md` says how to apply the rulesets when the repository is made public.
- `CODE_OF_CONDUCT.md` (the Contributor Covenant 2.1, with private reporting), a pull request template, a "Problem or question" issue form, and `.github/ISSUE_TEMPLATE/config.yml`, which turns blank issues off and links to private security reporting and to the documentation.
- `.github/dependabot.yml`: weekly, grouped update pull requests for the Python lock and for the actions. REMORA is left out; it moves only by a pin bump.
- `docs/bench/PUBLIC_TEST.md` says how a verified result (run by the maintainers on the benchmark runner, from the frozen tag) differs from a self-reported one (run by a participant). The "Gate result" form says that what it shares is self-reported.
- Servers shut down on hot inlet air (`electrical.it_load` 0.3.0). When a POD's inlet has been above 40 °C for 60 s, its IT load trips: it draws nothing, releases no heat, and the energy its workload asks for is counted in `it_kwh_lost`. It starts again when the inlet has been at or below 32 °C, the ASHRAE A1 allowable limit, for 300 s. The four values are profile parameters (`shutdown_inlet_c`, `shutdown_hold_s`, `restart_inlet_c`, `restart_hold_s`). The trip is a point, `thermal_trip`, an urgent alarm and an event, `it_load.thermal_trip`. Before, a run could report a POD at 60 °C with no IT energy lost. Runs where a POD gets that hot now lose IT energy, and the POD stops warming once its load has tripped. The committed examples in `docs/demo/`, the result report picture and the figure of the operator guide are made again: in `OP-03` with no control the hottest POD now peaks at 40.7 °C, not 61.7 °C, and 1,104 kWh of IT energy is lost, not 0.
- The main branch now carries the next benchmark version while it is being made. Season 1 runs on `benchmark-v1` at its tag (`git checkout benchmark-v1`). `bench run --tier quick` is a development run without `--allow-unfrozen`, and a run refused for its version says where the frozen one is.
- For the next benchmark version, not `benchmark-v1`: authority that changes during an incident (ADR 0028). A scenario event ends, passes on or narrows the mandate of a principal; every gate is told through one more premise; and each run counts the steps executed without a mandate. An approval from a person who has lost access is refused by the control path, whatever the gate, and counted. Four scenarios use it, `AD-11` to `AD-14`. A gate can give reason codes with a refusal (`reason_codes`, an optional field of the wire format), kept on the card and in `decisions.jsonl`, so a refusal for want of a mandate is told from one for another reason. Whatever the gate, each judgement also carries what was established as wrong with the step (`grounds`), and each run counts all its refusals by code and by ground (`refusals`). Card schema version 6.
- For the next benchmark version: the mandate record, a gate's own finding, and a gate that is not told the answer (ADR 0031). The register keeps every change to a mandate, with its time, who made it and why, and each proposal carries that record to the gate beside the premise (`PremiseSnapshot.mandate`, an optional `mandate` in the wire format). A gate that works out for itself who may act can ask to be given the record and not the premise (`derives_authority`, `ADC_GATE_DERIVES_AUTHORITY=1`); the run is judged by the premise all the same, and the card says that the gate was not told. A gate can state its own finding of whether the proposer holds a mandate (`authority_holds`), and with a refusal whether the mandate was never held or has ended (`reason_details`); both are optional. The control path establishes the same from the register, and each run in which a mandate was set counts the two kinds, the steps without a mandate the gate allowed, and where its finding or its kind is not the register's (`authority` on the run and on each row of `results`; the same on each judgement and in `decisions.jsonl`). `AD-11` and `AD-12` give the agent its mandate at their start, so their proposals carry the premise from the start. A run that sets no mandate, and its card, are what they were. From the second round of the first outside test (issue 31).
- `agentic-datacenter bench run` writes `decisions.jsonl` beside the card: each proposal, the gate's verdict and the reasons the gate gave, with the contract errors, limit errors and premises not established. The card is unchanged, so a card of the season is still the same file.
- The example gates in `examples/` are under the MIT licence. `docs/guides/bring-your-own-gate.md` says whose a gate is and when the contribution terms apply.
- `tools/season_registrations.py` reads whether an issue was open at a deadline from its close and reopen events, reads an edit history longer than one page to its end, checks on every edited issue that the entries of the history are whole texts, and lists an issue with a problem, never a guess, when an entry it needs was removed. The card is the same, byte for byte. The oracle's source and the frozen benchmark version are unchanged. `docs/bench/TIERS.md` says what machine each tier needs.
- The public test says whose the `full` run of a season is: the maintainers', for built-in gates, never a participant's gate on the maintainers' machine (`docs/bench/PUBLIC_TEST.md`).

Changed

The code owner's review moved to `main-review.json`, which the admin role may skip on its own pull requests. `CONTRIBUTING.md` says so: a pull request from anyone else is reviewed by the maintainer, and the maintainer's own are merged once the checks pass.
